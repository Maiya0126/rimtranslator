1 · 总体流程

扫描 Mod（4 来源 + 自定义目录）→ 选版本 (1.6 / 1.7)→ 选目标语言→ 提取 Keyed + DefInjected→ 术语库回填官方译名→ AI 翻译剩余 TODO→ 审阅对照表（可编辑）→ 确认写入（自动 .bak 备份）

2 · 功能规格

Mod 扫描器

  • 来源：创意工坊 workshop\content\294100本地 Mods游戏本体 Data（各 DLC）自定义扫描源（添加目录按钮，持久化，可增删）
  • 解析 About\About.xml（name / packageId / supportedVersions）与 LoadFolders.xml（版本子目录）
  • 列表搜索、来源筛选、版本选择（决定读根目录还是 1.6/1.7 版本目录的 Defs 与 Languages）

提取器（行为与参考模组一致）

类型源输出要点
KeyedLanguages\English\Keyed\*.xmlLanguages\<语言>\Keyed\值清空 + <!-- EN: 原文 --> 注释 + 已有翻译回填 + TODO + UNUSED 归并；旧 CodeLinked 目录改名处理
DefInjectedMod 的 Defs XMLLanguages\<语言>\DefInjected\<DefType>\<defName>.xml离线 XML 继承合并（Abstract / Name / ParentName）→ 按 DefInjectionPackage 字段遍历规则生成（string / List&lt;string&gt; / 嵌套类 / 列表索引路径）

输出目标（三档可选，默认原 Mod 目录）

  1. 原 Mod 目录：<Mod根目录>\Languages\<语言>\，与参考模组一致，玩家提取完直接可用
  2. 自定义目录：浏览选择，按 Languages 结构写入（对接本地开发副本）
  3. 独立汉化包骨架：自动生成 About.xml（packageId + 依赖声明）、LoadFolders.xml、Languages 目录——可直接发布的汉化 Mod 雏形

安全：覆盖任何文件前自动 .bak 备份；写创意工坊目录弹"更新会覆盖"警告。

术语库（Glossary）

  • 来源仅游戏官方翻译：Data\<DLC>\Languages\<语言>\ 的 DefInjected + Keyed
  • 构建"EN 原文 → 官方译名"对照库，首次构建后缓存；翻译前自动匹配回填，命中条目 TODO 秒消
  • 未命中条目发给 AI 时 prompt 附带术语约束（防自创译名，如 Warg=步行兽）

AI 翻译层

  • Player2 默认置顶 · 无需密钥 探测 GET :4315/v1/health → 授权 POST :4315/v1/login/web/019e12ba-6062-79ae-8c76-de13bea9af7a 取 p2Key → 请求 :4315/v1/chat/completions 带 player2-game-key 头；未运行引导启动桌面端
  • 供应商注册表照搬 RimTuber：Google / OpenAI / DeepSeek / Grok / GLM / OpenRouter / SiliconFlow / 本地模型 / 自定义
  • NormalizeEndpointUrl（强制）：完整端点不动；版本目录（/v1、/v4、/v1beta、/openai、/api/paas…）补 /chat/completions；纯域名补 /v1/chat/completions；405 单独提示自动补全请重试；测试与正式调用同一出口；不回写原值
  • 批量翻译：按 token 预算分批、编号对齐、失败重试一次后标记

审阅与写入

  • 审阅对照表：EN 原文 | 术语命中 | AI 译文 | 可编辑 | 状态（术语回填 / AI / 失败 / TODO）
  • 点"确认写入"才落盘（同样 .bak 备份）；完成报告含命中数 / 翻译数 / 失败数 / 输出位置

5 · 技术与结构

项决定
结构RimTrans.Core（逻辑库，无 UI 依赖，可单测）+ RimTrans.App（WPF 界面）
依赖零第三方 NuGet 起步：System.Xml.Linq / System.Formats.Tar / HttpClient / System.Text.Json
本机环境dotnet SDK 9.0.315 已装；关键路径见 HANDOFF.md 第 4 节
醒目提醒 · PatchOperation 后置到 V1.1
V1.0 不解析 PatchOperation（Add / Replace / Remove / Insert）。使用补丁动态增改文本的 Mod 会漏提取补丁部分（纯 XML + 继承合并估计覆盖约 90% 的 Mod）。V1.1 实现高频的 Add / Replace / Insert。每次发布说明必须向用户声明此限制；每次开发会话开始前重读本提醒。
开发红线（用户全局规则）
1. RimWorld 运行期间（进程 RimWorldWin64.exe / RimWorld.exe 任一存在）禁止构建，先征询用户。
2. 创意工坊目录写入必须走"覆盖警告 + .bak 备份"流程，不得静默写入。
3. 进入游戏的翻译文本禁 emoji、避 &（用 and / 和 或 &amp;）。
4. 一切 AI 端点调用必带 NormalizeEndpointUrl（405 修复），测试与正式同一出口。
